## การแก้ผลที่บันทึกคลาดเคลื่อน

- Chrome และ VS Code เปลี่ยนจาก `ไม่ผ่าน` เป็น `ผ่าน` เพราะผู้ทดสอบยืนยันหลังติดตั้ง build ล่าสุดว่าตำแหน่ง Picker ตรง caret แล้ว
- keyboard-only workflow เปลี่ยนเป็น `ผ่าน` สำหรับ Tier A ที่ทดสอบ ได้แก่ Notepad, Chrome และ VS Code ปัญหา Shift+Enter ที่เหลือเกิดเฉพาะช่องข้อความของ Codex และบันทึกเป็นข้อจำกัด compatibility แยกต่างหาก
- English Typing Handoff เปลี่ยนเป็น `ผ่าน` เพราะหมายเหตุเดิมเป็นอาการ rapid clicks ซึ่งไม่ใช่กรณี handoff
- rapid clicks เปลี่ยนจาก `ยังไม่ทดสอบ` เป็น `ไม่ผ่าน` หลักฐานหน้า Chrome พบ isolated high surrogate `U+D83D` แทรกระหว่าง `U+1F416` ทำให้หนึ่งรายการแสดงเป็น `�` และมีสถานะชั่วคราวกะพริบจนอ่านไม่ทัน
- queue full เปลี่ยนจาก `ไม่ผ่าน` เป็น `ยังไม่ทดสอบ` เพราะยังไม่มีหลักฐานว่าได้สร้าง active + 20 pending จริง อาการที่รายงานเป็น rapid-click corruption
- Explicit Copy เปลี่ยนจาก `ไม่ผ่าน` เป็น `ทำไม่ได้ใน environment` เพราะ Modern ไม่ถูกเรียกจาก elevated target และ Windows 10 Picker เดิมเปิดแทน จึงเข้า Explicit Copy UI ไม่ได้
- Clipboard manager ภายนอกเปลี่ยนจาก `ผ่าน` เป็น `ทำไม่ได้ใน environment` เพราะไม่มี manager ภายนอกติดตั้งอยู่
- ลบ escape sequence ที่เกิดจากการแก้ข้อความใน Terminal ออกจากหมายเหตุ reviewed โดยไม่เปลี่ยนไฟล์ผลดิบ

## ผลที่ไม่ผ่าน

### Explorer address bar

เมื่อกด `Win + .` จาก address bar ตำแหน่ง Picker ถูกต้อง แต่ Explorer เปลี่ยน control กลับเป็น breadcrumb ทันทีเมื่อเสีย focus ทำให้พิมพ์ต่อไม่ได้ ผู้ทดสอบยอมรับให้เป็นข้อจำกัดที่ไม่บล็อก MVP แต่ยังไม่ถือว่ากรณีนี้ผ่าน

### Windows High Contrast

ปุ่มและข้อความอ่านได้ แต่ Enter และ Shift+Enter ใน Search ใช้งานไม่ได้ และเมื่อ Theme ตั้งเป็น System แอปแสดง Light แทน Dark จนต้องเลือก Dark เอง

### Rapid clicks

เมื่อคลิก Emoji ถี่ ๆ หน้า Chrome ได้ sequence ที่มี `U+D83D` โดดเดี่ยว ทำให้เกิด replacement character `�` เช่นในชุดหมู `U+1F416` หลายตัว นอกจากนี้มีแถบสถานะสีแดงบริเวณเหนือแถบหมวดหมู่กะพริบเร็วเกินอ่าน และบางครั้ง Picker ค้างทั้งหน้าต่าง: control ทุกตัวกดไม่ได้และคลิกข้างนอกไม่ dismiss ต้องปิด Picker เอง เมื่อเปิด process ใหม่จึงกลับมาทำงานได้ตามปกติ

## ผลสำคัญที่ผ่าน

- Notepad, Chrome และ VS Code ผ่าน workflow หลักหลังแก้ caret placement
- Thai IME, dead key, single code point, variation selector, skin tone, mixed tone, flag, keycap และ ZWJ family ผ่านจาก Unicode code points ที่ปลายทาง
- Narrator อ่านสถานะได้ตามกรณีปกติ อาการ corruption จากการคลิกรัวจัดอยู่ใน queue ไม่ใช่ accessibility
- Clipboard ว่าง, Unicode text, image, FileDrop, Chromium custom/private formats และการเปลี่ยน Clipboard ระหว่าง delay ผ่าน รวมถึง target ปิดก่อน validation
- ช่วง runtime 15 นาทีตั้งแต่ 19:01:49–19:16:50 พบ process PID 8208, เก็บ 1,157 samples ทุก 500 ms และไม่พบ TCP/UDP socket (`observedSocketCount: 0`)
- Diagnostic logging ไม่เขียนรายการใหม่ขณะปิด และเมื่อเปิดมีเฉพาะ metadata ทางเทคนิค ไม่พบคำค้น, Emoji, Clipboard content หรือ target title ที่ใช้ทดสอบ

## ยังไม่ครอบคลุม

- ยังไม่ทดสอบ Windows Terminal และ queue full แบบ active + 20 pending
- Environment ไม่มี NVDA, จอสองตัวต่าง DPI และ Clipboard manager ภายนอก
- focus-change race, elevated target, Explicit Copy และ Clipboard History ยังไม่มีหลักฐานเพียงพอให้ถือว่าผ่าน
- หลังรายงานรอบนี้เพิ่ม agent-runnable WPF desktop regression ซึ่งทำให้ focus/rapid-click failure เกิดซ้ำได้ 3/3 รอบ สาเหตุคือ pointer click ถัดไป activate Picker กลับระหว่าง target validation/injection และ target ที่ไม่มี child HWND ไม่สามารถคืน editable state ด้วย native `SetFocus` อย่างเดียว แก้ด้วย no-activate style เฉพาะช่วง queue และ UI Automation focus snapshot แล้ว stress 15 รายการผ่าน 10/10 รอบ; ผล Chrome/Explorer จริงยังรอ maintainer retest ก่อนเปลี่ยนแถวที่ไม่ผ่าน
- socket observation ไม่ใช่ packet capture และอาจพลาดการเชื่อมต่ออายุสั้น จึงต้องอ่านผล network ร่วมกับ automated source/runtime gates
